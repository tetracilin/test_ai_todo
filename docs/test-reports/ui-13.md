## 7 Evaluation and recommendations

### Product findings

- **P1 (suspected production bug, NEEDS_DECISION): `ui/src/pages/InviteLanding.tsx` line 211.** `useState<AgentAdapterType>("claude_local")` is the initial adapter, but `joinAdapterOptions` is `["hermes_gateway"]` (line 20). The `<select>` shows Hermes Gateway, but state stays `claude_local` unless the user changes the select, and a one-option select never fires `onChange`. `acceptInvite` is then called with `adapterType: "claude_local"` (line 338), which contradicts the fork's Hermes-only join policy. The existing test only checks the option list. The fix is probably to initialise state to `joinAdapterOptions[0]`, with a test that submits an agent invite and asserts `adapterType: "hermes_gateway"`. I did not add that test because it would fail today.
- `ui/src/pages/InstanceGeneralSettings.tsx`, `InstanceExperimentalSettings.tsx` and the `InviteLanding` tests still contain the Paperclip Cloud "managed" flows (`/cloud/logout`, `managedKeys`). These are upstream concepts that still pass. The product owner should confirm whether Cloud-managed mode is intended to stay in the fork.

### Recommendations

1. Fix P1 and add the agent-invite submission test.
2. Make `flushReact()`-count waits condition-based in the files listed in section 6. IssueDetail is already improved.
3. Replace CSS-class assertions with `data-*` attributes or aria state where possible. The design-token policy keeps churning those classes.
4. Table-drive the InstanceExperimentalSettings toggle tests (about 12 tests collapse into one parameterised case).
5. Remove the unused Claude-login mocks from NewAgent.test.tsx, or add the Claude-login flow tests back if that flow is still in the product.
6. Move `root.unmount()` into `afterEach` for PluginPage and PluginSettings.
