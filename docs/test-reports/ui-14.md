## 2 Summary

Every file was read in full and checked against the production module it exercises (`Routines.tsx`, `Search.tsx`, `Secrets.tsx`, `ImportFromVaultDialog.tsx`, `TeamCatalog.tsx`, `ImportSkillsFromProjectDialog.tsx`, tools tabs, and so on). The subjects all still exist in the fork and no test asserts upstream-only behaviour or a stale default. The dominant defect class is V3 (timing): helpers that poll for a fixed number of flush cycles, and fixed `setTimeout` sleeps that race a production debounce. This is the same class that #161 fixed for `CompanySettings.test.tsx`. Two files had assertions that could not fail (V2), one had three duplicated tests (V9), and two tests had misleading names (V6).

## 3 Variances

- Platform is Windows 11. All 24 files are jsdom/node UI tests with no POSIX-only dependencies, so none needed an ENV classification. No failure of any kind was observed (see section 8).
- Tests were run one vitest process at a time from the repo root with `npx vitest run <file>`. A first attempt with `--project ui` failed at start-up because the root config names projects differently ("No projects matched the filter ui"); that is a command-line error, not a test result, and the filter was dropped.
- Time-bounded polling was verified only by passing runs on an idle machine. The point of the change (robustness on a loaded CI runner) cannot be demonstrated locally; it is justified by the #161 incident.
- Not verified: the real-clock 250-300ms debounces in `Search` and `ImportFromVaultDialog` remain real time (fake timers would interact badly with react-query's scheduler); they are now polled against a deadline instead of slept.

## 7 Evaluation and recommendations

Product findings: none. No production bug is suspected and no test was bent to pass.

Coverage gaps (reported, not added):

1. `ImportSkillsFromProjectDialog`: only pure helpers are tested; there is no render test for select-all, deselect-all, rename-on-conflict or the import mutation error path.
2. `SkillStudio`: no failure path for save/create (`updateFile` or `create` rejecting) and no version/test-run coverage despite the API surface being mocked.
3. `TeamCatalog`: install mutation failure and the `scripts_executables` confirm gate are untested.
4. `PasteConfigTab`: `importMcpJson` rejection and invalid JSON are untested.
5. `profile-model`: `parseEntries` with entries referencing unknown catalog ids and mixed include/exclude for one app are untested.
6. `StatusCards/format`: `estimateStatusCardCost` boundaries (cap larger than daily budget, interval below one minute, reactive with a cap) and the `reactive` branch of the settings form preview.
7. `Search`: pagination (`hasMore` / load more) has no test.

Recommendations: (a) extract the repeated `waitFor` helpers into one shared test util that wraps `vi.waitFor`, as `SkillStudio.test.tsx` already does, instead of per-file reimplementations; (b) prefer role/label queries over Tailwind class selectors; (c) unmount roots in `afterEach` so failing assertions do not leak React roots.
