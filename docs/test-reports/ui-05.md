## 2 Summary

## 7 Evaluation and recommendations

Product findings (need an owner decision, not a test change):
1. **NewAgentDialog shows no runtime for the fork's only manually configurable adapter.** `isValidAdapterType` allows only `hermes_gateway`, but `adapter-display-registry.ts` marks `hermes_gateway` `hideFromVisualSelection: true`, and `NewAgentDialog` also filters the grid with `isVisualAdapterChoice`. Result with real modules: "No agent runtime is available on this instance. Ask an operator to set PAPERCLIP_SELECTABLE_ADAPTER_TYPES ...". The committed test hides this with a mock. Either the display flag should be removed for `hermes_gateway` (fork policy), or the dialog should not apply the visual filter on the manual path. The same mock pattern exists in the OnboardingWizard tests, so the onboarding adapter grid may have the same issue. Once decided, drop the `../adapters/metadata` mock (I proved the test body works with the real module except for this).
2. The error text in that empty state still points at upstream-style `claude_local` guidance; worth aligning with fork wording.

Coverage gaps (report only):
- No component test drives `useSelectableAdapterTypes` with a non-null set (server-advertised selectable adapters), the main fork-owned selection policy, in OnboardingWizard.
- `NewAgentDialog` has no test for the server `selectable: false` / `disabled: true` paths.
- `Layout` has no test for the archived-company bounce (mocked to null; covered elsewhere per comment) or mobile open-sidebar interactions.
- `KanbanBoard` has no drag-and-drop dispatch test (only `resolveKanbanTargetStatus`).

Recommendations: replace remaining fixed-tick settle helpers (OnboardingWizard.step, PropertiesPanel) with a shared deadline-based `waitFor`; extract the triple-copied `cssBlock` helper and the Layout render boilerplate into test-only helpers in a separate cleanup PR.
