All 28 files were read in full and checked against the production sources and migrations they exercise. Headline findings:
1. `scheduling-schema-migration.test.ts` was skipped everywhere: it ran only with `TEST_DATABASE_ADMIN_URL`, which nothing in the repo sets. Rewritten to fall back to the embedded Postgres harness. It now runs and passes (4/4).
2. `packages/db/scripts/clean-poisoned-claude-sessions.test.ts` is never executed by `pnpm test` or t3-nightly: `packages/db/vitest.config.ts` only includes `src/**/*.test.ts`. With a temporary config it passes 15/15. Config is out of scope for this audit.
3. A DB-free static guard in `client.test.ts` sat inside the embedded-Postgres describe and was silently skipped on hosts without embedded PG. Moved to a plain describe.

## 3 Variances

- Platform is Windows 11. Embedded Postgres reports "supported" but is slow: start plus migration replay takes 30-45 s under contention (other shards ran concurrently), against 20-30 s explicit per-test timeouts. In the baseline whole-package run (105 tests: 68 passed, 30 failed, 7 skipped) every embedded-PG failure was a vitest timeout, classified ENV. These could not be shown green here: backup-lib (4 of 8), built-in-agent-unique-marker, client.test (14 DB tests), company-secret-proposals, connections-v3, decision-queue, inbox-archive, issue-comment-derived-attribution (3), issue-comment-on-behalf, nested-skill-folders, status-card (passes with a 150 s timeout, verified with a temporary copy that was deleted), pipelines-schema (beforeAll 20 s timeout, so its test was skipped).
- `backup-lib.test.ts` "restores fallback COPY data ..." fails on Windows with `spawn psql ENOENT`. It forces `PAPERCLIP_PG_DUMP_PATH=/bin/false` and its restore path needs a `psql` binary on PATH. ENV (V8).
- `embedded-postgres-native.test.ts`: two `runIf(platform !== "win32")` tests are skipped here by design.
- Unedited files were not re-run individually beyond the baseline run.

## 7 Evaluation and recommendations

Product / config findings:
- P1. `packages/db/scripts/*.test.ts` is outside the db vitest include. Add `scripts/**/*.test.ts` to `packages/db/vitest.config.ts` in a separate PR.
- P2. Nothing in CI sets `TEST_DATABASE_ADMIN_URL`; the scheduling migration test had never run. It now runs through the embedded harness and passes against migrations 0227 + 0228.
- P3. Embedded-PG tests use 20-30 s per-test timeouts, which fail on slow or contended runners (status-card and company-secret-proposals already carry comments about this). Consider a shared timeout constant.
- P4. Each migration-replay test migrates the full chain (234 files) from scratch; a shared template database would cut slow-test time.

Coverage gaps (reported, not added):
- backup-lib: no restore test for a corrupt or truncated file; retention is tested for the monthly tier only.
- client-options: no test for a non-numeric `DATABASE_POOL_MAX` such as "abc".
- pipelines-schema: no cross-company FK negative case; no cascade assertions.
- runtime-config: no test for malformed config JSON or `PAPERCLIP_INSTANCE_ID`.

No suspected production bugs were found.
