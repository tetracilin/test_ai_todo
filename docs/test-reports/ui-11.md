## 3. Variances

- Windows host: only `ui` (jsdom/node) tests were run. They are not POSIX-bound, so no ENV skips were needed apart from the items below.
- The five baseline failures were classified:
  - `no-browser-model-calls` (3): REAL on Windows (allowlist keys used `\` path separators so the `sk-` allowlist never matched, REAL portability defect, fixed) plus ENV/perf (synchronous whole-tree reads per test exceeded the 5 s timeout under load; fixed by reading the tree once).
  - `AgentToolsTab` (2 of 4 initially, all 4 on the isolated re-run): ENV (cold dynamic import of the heavy page module charged to each test's 5 s budget). Passes with `--testTimeout=90000`; fixed structurally by importing once in `beforeAll`.
- Large React suites were not audited line by line (see section 7).
- Not run: browser/Playwright suites (out of scope).

## 7. Evaluation and recommendations

- Quality of this shard is high: pure-helper suites are deterministic, fixtures are typed against `@paperclipai/shared`, and negative paths (null, empty, unsafe paths, fail-closed states) are well covered.
- Recurring hazard: dynamic `await import()` of heavy page modules inside a test body. Other UI page suites outside this shard likely have the same cold-import timeout on slower hosts; a shared `beforeAll` import pattern is recommended.
- Recurring hazard: iteration-bounded polling helpers; prefer a shared time-bounded `waitFor` test utility (three copies now exist).
- `no-browser-model-calls` is a repo-scanning guard; any other repo-scanning test should normalise `path.sep`.
- Coverage gaps not filled (not cheap): negative paths of `AppsConnect` OAuth failure states beyond "Try again", and real timer control (`vi.useFakeTimers`) for the debounced autosave and min-spinner flows would remove the remaining real sleeps.
- Product findings: none. No suspected production bugs.
