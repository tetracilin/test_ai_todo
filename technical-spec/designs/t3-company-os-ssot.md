## Problem Statement

The T3 Paperclip fork has grown through multiple phases and its planning surface no longer
tells one story. Of the three files meant to steer it, only `backlog.md` (the 34 PC-xxx
story backlog) is fork-native; `roadmap.md` is upstream Paperclip's generic roadmap and
`design.md`/`DESIGN.md` (same file — Windows case-insensitive) is upstream's UI
design-language doc. Meanwhile the product vision has moved: a plugin-first, agent-native
**personal company operating system** that travels with the founder to any project.
The three files must be replaced with a coherent source of truth: `roadmap.md` (identity +
high-level user stories), `backlog.md` (incremental work packages), `design.md`
(architecture notes) — without breaking the fork's upstream-sync discipline or the repo's
existing references.

## Demand Evidence

- A field engineer, unprompted, used a chat client (Zalo) to submit evidence and ask
  clarifications, then **recruited the PM as a human assistant for data entry**. The PM
  orchestrated, reviewed, and summarized evidence upward to the CTO. The org manually
  invented the missing product feature — the strongest possible demand signal.
  (Platform decision: the supported channels are **Discord and WhatsApp** — chosen for
  **stability and integration support** over Zalo; the observation proves the
  conversational-capture behavior, not a specific app.)
- Engineers "plan like memoryless LLM agents": they don't know what's next and need
  re-briefing at every task start. The re-brief is an unbuilt feature with observed demand.
- Budget is formally allocated (internal paying customer). LibreOffice/WOPI artifact
  editing, the Discord bridge, and partial staging + nightly CI/CD have already shipped.

## Status Quo

Evidence flows through Zalo chat and a human PM doing data entry; planning happens on a
wide screen at the desk; capture happens on the move where forms lose. Planning docs are
scattered: T3 content in an uncommitted backlog, upstream artifacts wearing the roadmap
and design filenames. Prior commercial self-hosted tools at the company died because they
were too buggy and adapted too slowly — adoption is fragile.

## Target User & Narrowest Wedge

**The engineer on the move** (Zalo, conversational, evidence in hand) and **the PM as
orchestrator** (review, summarize, brief). Wedge = the recorder loop (job order → card →
evidence gate; PC-001..007 + PC-402 pilot) reached through a **WhatsApp
evidence-and-briefing bot** (the Discord bridge is shipped; WhatsApp is the second
instance of the same chat-bridge abstraction) with four verbs:
1. **Capture** — photo/message → agent structures into `{card, evidence_type, caption}`,
   confirms in one line, correction path included ("wrong card? reply the number").
2. **Re-brief** — "brief" (or proactive at task checkout): current card, open evidence
   gaps, next task.
3. **PM digest** — daily summary to PM/CTO: evidence filed, cards blocked on missing
   evidence — replacing the PM's manual summary and making her the champion.
4. **Tabular records** — Teable is the **system of records** for flat tabular data (OEM
   catalogs, BOM line items, design-dossier sections). The tool reads and writes Teable
   tables directly: the agent files structured data (an OEM row, a BOM item) into Teable
   and links the row on the card as an external object (provider `teable`). Agent
   *authoring* of Teable rows is a **new story — PC-010 "Agent tabular read/write to
   Teable"** (OV-3): PC-005 stays one-directional card mirroring; PC-010 carries its own
   ACs (write conflict policy, schema mapping, which bases/tables are agent-writable).
   Teable is already stood up, replacing Fibery after a successful trial (AD-022).

All four verbs communicate with engineers in **Vietnamese** (their working language).
Development stays **English**: code, prompts, docs, and agent internals are English for
efficiency — the Vietnamese/English switch happens at the agent's **system prompt**
layer. **Record-language convention** (OV-8): captured content (captions, clarifications,
evidence descriptions) stays **verbatim Vietnamese** — it is evidence, never
machine-translated at capture; structure (card titles, dossier section headers, export
scaffolding, story IDs) is **English**; the agent may add an English one-line gloss on
filing. The institutional-memory corpus is therefore deliberately bilingual, not
accidentally so. **Confidential content mitigation** (AD-021/C16 collision with chat capture):
the bot refuses confidential (defense/B2G) material with NAS drop-folder instructions and
stores nothing — the same rule PC-004 AC3 already specifies for the Discord bridge; cards
carry NAS path references only. The bot's capture prompt names the "do not send"
categories, and a bot-side warning fires on suspected confidential content. **The
control is structural, not the prompt** (OV-9): per C16, confidential (defense/B2G)
projects are never onboarded to chat bots at all — their engineers use the NAS
drop-folder path exclusively; bot-side refusal is defense-in-depth against accidental
sends on non-confidential projects, because refusal fires only after content has already
transited the chat platform's servers.
**Fallback:** the Discord bridge is already shipped — if WhatsApp Business API access is
blocked or metered beyond budget, the pilot runs on Discord and WhatsApp re-scopes to a
later work package. Known adoption risk: field behavior already routed around Discord
once (the Zalo observation), so the Discord fallback is a technical fallback, not a
proven adoption path — the pilot on Discord carries an explicit abort criterion (if
after one week <50% of evidence arrives via the bot, stop and revisit the channel
decision rather than pushing adoption uphill).

## Constraints

- Fork discipline: this is a **hard fork with an independent roadmap** — nothing is ever
  contributed back to paperclipai/paperclip. `upstream` stays configured for **one-way,
  selective pulls only** (security fixes and useful core improvements, cherry-picked at
  the owner's discretion); divergence is accepted and expected. LICENSE/NOTICE are
  preserved when copying upstream code. **`main` is the development branch** (CEO-review
  decision 1A: `integration/paperclip` sits 51 commits behind main with nothing main
  lacks — it is retired, and CLAUDE.md/AGENTS.md fork-identity sections are corrected in
  this same PR; no `upstream` remote is configured until the first actual cherry-pick).
  This restructure lands as a single PR into `main`. Rewriting upstream-owned files
  (`roadmap.md`) carries a merge-conflict cost only when a selective pull touches them. Mitigation, honestly stated:
  a `.gitattributes` `merge=ours` entry needs a driver definition in each clone's git
  config (`git config merge.ours.driver true`) — `.gitattributes` alone cannot ship it,
  and the driver only fires on both-sides-changed merges, so it is a convenience, not a
  guarantee. The primary protection is **automated** (CEO-review decision 2A, scoped per
  OV-7): a CI guard script `scripts/check-ssot-guards.mjs` with two checks — (a)
  **strict tree-path check**: no case-colliding `DESIGN.md` or `ROADMAP.md` path may
  exist in the git tree, zero exceptions; (b) **curated reference check**: only a small
  list of load-bearing files (CLAUDE.md, AGENTS.md, README.md, package.json scripts,
  `scripts/check-token-gates.mjs`) is checked for references to relocated old paths — no
  repo-wide grep, no rotting allowlist. The recurring checklist in `doc/UPSTREAM-SYNC.md`
  becomes the backstop, not the only defense:
  (a) after every sync, delete any re-added upstream `DESIGN.md` **or `ROADMAP.md`** —
  in git's tree each is a *different path* from the fork's lowercase `design.md` /
  `roadmap.md`, and the pairs collide on one file at checkout on Windows/macOS every
  sync, not just once; (b) verify the three SSoT files' content provenance (fork-owned,
  no silently merged upstream content); (c) grep for new dangling references to
  relocated paths. The `.gitattributes` merge entry covers exactly `roadmap.md`,
  `backlog.md`, and `design.md`. `ROADMAP.md`'s reference set (README.md,
  CONTRIBUTING.md, cli/README.md, `.github/PULL_REQUEST_TEMPLATE.md`, issue templates)
  joins the migration list alongside `DESIGN.md`'s.
- Windows case-insensitivity: `design.md` IS `DESIGN.md`, which AGENTS.md, CLAUDE.md, and
  `check:token-gates` reference as the UI token source of truth — its content must be
  relocated (e.g. `docs/designs/DESIGN-UI.md`) and every reference updated in the same change.
- Confidential (defense/B2G) content never enters chat bridges or the repo (AD-021, C16).
- Language boundary: engineer-facing conversation is Vietnamese; the official language
  for development, prompts, and docs is English (efficiency). The switch is implemented
  at the agent's system prompt — never by translating code, prompts, or internal docs.
- pnpm workspace layout and the K6 domain map bind stories to existing services — no new
  tables without cause.

**Glossary** (identifiers used in this doc): *K6 domain map* =
`docs/migration/test-ai-todo-domain-map.md` (which Paperclip service owns each business
concept); *AD-xxx* = architecture decisions from INFRA-DESIGN-v1 Patch Set 003; *C13/C14/

## Premises (agreed, revised after cross-model challenge)

1. **Identity** — personal, portable company OS; portability (company import/export) and
   plugin-first edges are hard constraints. The fork is a hard fork: one-way selective
   pulls from upstream Paperclip, never contributing back — the roadmap is fully
   independent.
2. **Wedge** — the recorder loop with one engineer; everything else stages behind it.
3. **The agent is the form** — conversation captures (chat bridges: Discord shipped,
   WhatsApp next), the board plans; the agent structures, files, summarizes, and briefs.
   Engineers in the field never fill a form.
4. **Two-tier integrations** — Tier 1 (default for most plugins): file store + version
   control with viewing for drawings, PDF, docx/xlsx; v1 workflow is download → edit in
   native desktop tool → re-upload with version notation. Tier 2 (edit-in-app, per-tool):
   WOPI/LibreOffice shipped; next candidates Penpot, Excalidraw, draw.io. FreeCAD, KiCad,
   Figma, email enter at Tier 1 first.
5. **Self-development, charter-constrained** — feedback → Claude Code → staging → nightly
   is first-class because adoption dies on buggy, slow-to-adapt tools (observed with prior
   self-hosted apps). Charter: consolidation, bugfixes, and user-feedback adaptation —
   not autonomous feature invention — until the wedge metric is green. Health metric:
   merged auto-PRs vs. regressions/rollbacks vs. engineer-facing usage improvements,
   reviewed at 60 days.

## Approaches Considered

### Approach A: In-place rewrite (minimal viable)
Overwrite the three files; relocate upstream roadmap to `doc/UPSTREAM-ROADMAP.md` (since
removed outright — the fork keeps no upstream roadmap archive) and UI
design principles to `docs/designs/DESIGN-UI.md`. Fast (CC ~10 min) but leaves dangling
references and no cross-linking. Rejected: reference breakage on DESIGN.md is a real cost.

### Approach B: Three-file SSoT + reference migration
A plus: update every reference (AGENTS.md, CLAUDE.md, check scripts, README), each doc
declares itself part of the SSoT trio and links the other two, CLAUDE.md reading order
updated. Clean, human-readable (CC ~25 min).

### Approach C: B + machine-readable docs (chosen)
B plus YAML frontmatter on the two files that lack it (`roadmap.md`, `design.md` —
`backlog.md` already carries the pattern) and success metrics embedded per work package,
so agents and the self-development loop can parse, check, and update the docs. The docs
become agent-operable surfaces — the product thesis applied to itself (CC ~35 min).

Frontmatter shape (example, per file):
```yaml
---
id: T3-ROADMAP            # T3-BACKLOG / T3-DESIGN for the others
role: roadmap             # roadmap | backlog | design — the SSoT trio
status: ACTIVE
owner: tetracilin
siblings: [backlog.md, design.md]
updated: 2026-09-01
metrics:                  # backlog.md only: per-WP acceptance metrics
  wp0_evidence_via_bot: ">=80%"
---
```
Consumer, honestly stated (OV-6): **today** the consumer is agents reading the trio via
CLAUDE.md's reading order — the frontmatter costs minutes and documents targets even
while unconsumed by automation. The self-development loop checking `metrics` against
usage instrumentation is the **intended future** consumer; it does not exist yet and
nothing in this change depends on it.

## Recommended Approach

**Approach C.** The tool's identity is agent-native and self-developing; its steering
documents must be operable by the same agents. Delta over B is minutes; the frontmatter
convention reuses the pattern `backlog.md` already carries.

Target shape:
- `roadmap.md` — identity ("personal company OS / execution → institutional memory"),
  high-level user stories (engineer, PM, CTO, founder-as-portable-operator), horizons:
  NOW (recorder loop + WhatsApp bot), NEXT (Tier-1 file plugins, gbrain, skill repo),
  FUTURE (Tier-2 editors, LLM adapter expansion, email, FreeCAD/KiCad/Figma).
- `backlog.md` — work packages, sequenced per OV-2: **the recorder substrate first**
  (PC-001 evidence gate, PC-002 dossier, PC-004 intake, PC-007 evidence linking), then
  **the four-verb bot (WP-0) on top of it, both inside Slice 1's** one-engineer pilot —
  the bot is not staged ahead of the cards it files against. PC-010 (agent Teable
  read/write) joins Slice 1 for verb 4. Remaining PC-xxx epics follow as before.
  Acceptance metrics live in a single file-level `metrics:` map in `backlog.md`'s
  frontmatter, one key per WP (as in the example below) — not per-WP frontmatter blocks.
- `design.md` — architecture note: control plane + adapters, two-surface model
  (conversation captures / board plans), two-tier plugin integration, chat-bridge
  abstraction (Discord instance → WhatsApp next), gbrain memory, company skill repo
  (hermes-agent pattern), self-development pipeline and its charter + health metrics.
- Relocations: upstream roadmap → `doc/UPSTREAM-ROADMAP.md` (later removed outright); UI design language →
  `docs/designs/DESIGN-UI.md`; all references updated in the same commit.

## Success Criteria

Two deliverables, two definitions of done:

**Landing hygiene** (CEO-review decision 3A): the PR commits the currently-untracked
`backlog.md` as part of the trio, and the pre-existing uncommitted `AGENTS.md` edits are
diff-reviewed first — folded in if related to fork identity, committed separately if not.

**This change (the doc restructure) is done when:**
- All three stacked PRs (below) are merged into **`main`** with zero dangling references
  in the curated file list (`check:token-gates` still green), the `.gitattributes` merge
  rule is in place, `doc/UPSTREAM-SYNC.md` is **rewritten for the hard-fork cherry-pick
  model** (its merge-based workflow and is-ancestor invariant removed — OV-1), and the
  full referencing-doc sweep is done: README.md, CONTRIBUTING.md, cli/README.md,
  `.github/` templates, `docs/migration/test-ai-todo-inventory.md`, `backlog.md`
  frontmatter, and `.claude/agents/*` files all consistent with the retired
  `integration/paperclip` and relocated `DESIGN.md`/`ROADMAP.md`.

**Landing shape** (OV-10): three stacked PRs into `main` — **PR1** AGENTS.md
reconciliation (after diff review); **PR2** doc trio + relocations + full reference
sweep; **PR3** guard script + CI wiring. The pre-code assignment (WhatsApp API
verification, PM observation) runs in parallel and is blocked by none of them. Honest
effort for the whole restructure: ~1–2 h CC, not minutes (OV-6).

**The wedge pilot (WP-0, tracked in backlog.md — not gating this change) is done when:**
- One-week pilot, one engineer + one PM: **≥80% of evidence items arrive via the bot
  without PM re-entry**. Measurement (OV-5): self-measuring — every evidence row carries
  a source field (`bot` | `manual`); the ratio is queried from the system, not
  hand-tallied. Bands: **<50% abort** (revisit channel decision); **50–79% iterate**
  (diagnose the top blocker, run one more week); **≥80% pass**. "The PM's manual summary
  stops being written" is a secondary signal, not part of the DoD — it depends on the
  digest verb, whose WhatsApp template/pricing question is still open. Engineer-facing
  interactions run in Vietnamese via the agent's system prompt — part of the definition
  of done; prompts and code stay English.
- Engineer usage metrics instrumented (adoption-drop alarms), auto-PR health metric
  reviewed at 60 days.
